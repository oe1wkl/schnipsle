# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- Repository foundation: Cargo workspace (`schnipsle-core`, `-import`, `-export`, Tauri 2 shell), TypeScript UI, CI, dependency licence checks, macOS bootstrap script.
- Architecture decision records ADR-0001 to ADR-0035.
- Vault format specification, draft revision 0.15 (notes, front matter, tags, links, attachments, music in ABC, song sheets in ChordPro, history, trash, smart folders, imported notes and the import log).
- Hashtag extraction in `schnipsle-core` following format.md §5.3, with the specification examples as tests.
- Vault access in `schnipsle-core`: list notes (with iCloud placeholders), read, atomic write with conflict detection, create (spike, see docs/spikes/ios-vault.md).
- `tauri-plugin-vault-access`: iOS folder picker with security-scoped bookmarks and iCloud download requests (spike).
- File coordination on macOS and iOS (ADR-0015): notes are read and saved through `NSFileCoordinator`, so iCloud Drive and other apps cannot change a note between the conflict check and the save. New crate `schnipsle-apple`; `schnipsle-core` gains a `Coordinator` trait.
- Changes made elsewhere now arrive as file events instead of being polled every 3 s: `notify` on desktop, an `NSFilePresenter` on macOS and iOS. The UI gets one `vault-changed` event per burst of changes.
- iCloud sync conflicts are shown: when two devices changed a note before syncing, a banner offers to keep this version or use the other one. The version not kept is stored in the note's history (`.notesapp/history/<id>/`, format.md §7) before iCloud is told the conflict is resolved, and the note gets `id`, `created` and `modified` in its front matter.
- Every save keeps the note's front matter up to date (format.md §4): `id` and `created` are added the first time the app writes a note, `modified` on each change. Keys added by other tools are preserved, and a note is never rewritten just by opening it.
- Copies of a note with the same `id` (format.md §4), such as the `Name 2.md` copies iCloud Drive makes in a sync conflict, are shown in the conflict banner: keep this version or the copy's (the other text goes into the note's history and the copy is removed), or keep both as separate notes, in which case the later one gets a new `id`. Copies in other folders are found through the search index; copies in the same folder also while the index is still being built.
- New note editor (CodeMirror 6, ADR-0007) with inline live preview: headings, emphasis, strikethrough, inline code and links are shown formatted, their Markdown markers appear only on the line being edited, and task boxes can be ticked. A button switches to plain Markdown source; the choice is remembered. The front matter is shown muted, and front matter written on save no longer moves the cursor or enters the undo history.
- Note list: sort by recently changed or by title (ignoring case and accents). New notes are named after their title, and when you leave a note whose title changed, its file is renamed to match (format.md §3); renames never replace another file.
- Trash (format.md §8): Delete moves a note unchanged to `.notesapp/trash/`, with Undo; a Trash view lists deleted notes and restores them. Notes without `id` and repeated ids get their own trash names (format.md 0.5).
- Notes in the Trash view can be read before restoring them: picking one shows it read-only in the editor, images included; restoring it opens it for editing.
- Vaults follow the layout of format.md §1: a vault is a folder with `.notesapp/vault.yaml`, and its notes live in `notes/`. Picking a folder without `vault.yaml` asks first and then moves everything visible in it into `notes/` (relative links keep working; hidden files such as `.notesapp/` stay), so existing note folders, including the M1 test vault, are converted only with consent. A vault written by a newer format version, or with a damaged `vault.yaml`, opens read-only with an explanation. Picking a folder inside a vault is refused.
- Notes that turn up outside `notes/` (`.md` files and folders with notes at the vault root, e.g. saved by an older build on another device) are detected when the vault opens and when its root changes. A banner offers to move them into `notes/`: notes with a taken name get `-2`, `-3`, …, folders with a taken name stay where they are, and nothing is replaced.
- Images and other attachments (format.md §5.5, §6): paste or drop files into a note, or pick images with the Image button. Each file is stored once per content at `attachments/<h0h1>/<sha256>.<ext>`, with a sidecar recording its original name, and the note gets a link relative to it (`![name](../attachments/…)`; other files get a plain link). Live preview shows images, also ones next to the note; on the line being edited the Markdown appears in front of the image, which stays visible.
- Image and file links keep working when a note moves to another folder (format.md 0.7 §5.5, ADR-0016): when a restore from the trash falls back to `notes/`, or notes are moved in from the vault root, relative links that worked before are rewritten, and the previous text goes into the note's history. URLs, note links and links that were already broken stay as written.
- Version history for every note (format.md §7, ADR-0011): a version is stored after a 30-second typing pause, when you leave a note, before it is deleted, and before another version replaces it (a change from elsewhere, or either side of an editing conflict, which so far dropped the losing text). A version equal to the last stored one is skipped. When a vault opens, old versions are thinned in the background: all are kept for 7 days, then the last of each day for 90 days, then the last of each week.
- History view: the History button shows the open note's earlier versions, newest first. Pick one to read it (in preview or source, like the editor), then restore it (the text it replaces goes into the history first, and a change made elsewhere meanwhile stops the restore) or copy it as a new note with its own `id`.
- Tables (GitHub Flavored Markdown) show as tables in the live preview, with column alignment; their Markdown appears while the cursor is in the table. Cells show their text as written for now.
- History retention can be set per vault in `.notesapp/settings.yaml` (format.md 0.8 §7, ADR-0017): `history_keep_all_days` (default 7) and `history_keep_daily_days` (default 90).
- Own menu bar on the desktop: File (New Note, Open Vault…, Close Window), Edit, Window (Minimize, Zoom, Full Screen) and, on macOS, the app menu. "Close Window" no longer appears twice.
- Search index in `schnipsle-core` (ADR-0009): SQLite with FTS5 (bundled), per note its title, plain text, tags with their hierarchy, note links and linked files; a per-device cache that rebuilds itself when its schema changes or the file is damaged. The app keeps it current: a background sync when a vault opens (reading only files whose modification time or size changed), then change events and its own writes; trashed notes are indexed too.
- Tag folders (ADR-0008) in a collapsible tree above the note list (on the phone a Tags view of its own): every top-level tag with its note count, hierarchy levels (`#projekte` › `#projekte/tuner`) and combinations with co-occurring tags as intersections up to three tags deep, plus the untagged notes. A tag is shown in its most used spelling; the trash does not count. Picking a folder filters the note list; a line above it says what is shown, with "Show all".
- Full-text search in a search field above the note list: words match as prefixes ignoring case and diacritics, `"phrases"`, `#tags` (with their subtags), `-` to exclude, `OR` and parentheses; best matches first (titles count more), each with a snippet that marks the hits. Escape returns to what the list showed before. The trash is not searched.
- Performance test with 20,000 generated notes (N-03), run in CI in release mode: every search and tag-folder query must stay under 200 ms; on a Mac they take 2–48 ms.
- The search understands the full query language (`docs/manual/query-language.md`): `created:` and `modified:` with years, months, days, `today`, `yesterday`, `7d`/`2w`/`3m`/`1y`, comparisons and ranges, in your local time zone; `has:image|task|link`, `is:pinned|untagged`, `in:trash` (trash hits are marked and can be restored from the Trash view) and `tag:x`. The index rebuilds itself once for the new fields.
- Song sheets (` ```chordpro ` blocks, format.md §5.7) are searchable by their lyrics without the chord brackets and by title, subtitle, artist, composer and lyricist; ChordPro comments and tablature are left out. `has:chord` finds notes with chords, `chord:Am` notes with that chord. The index rebuilds itself once more.
- Music scores (` ```abc ` blocks, format.md §5.6) are searchable by their titles (`T:`), composers (`C:`) and lyrics (`w:`, `W:`). Syllables are joined into words, so `aufgegangen` finds `auf-ge-gan-gen`, and the accents of ABC (`\"u`, `&uuml;`) count as letters. The notes, other fields and `%` comments are not searched. The index rebuilds itself once more.
- Song sheets are rendered and transposed in `schnipsle-core` (ADR-0030), ready for the editor and the exports. Chords go over their syllables in verses, choruses, bridges and tabs, and `{chorus}` repeats the last chorus. Transposing adds up the block's `transpose=`, the viewer's choice and `{transpose}` lines, and names each chord as the new key wants it: B♭ in F, A# in F#. German names (`H`, `B`) work per block or as the vault default `chord_notation: german` in `.notesapp/settings.yaml` (format.md 0.15). Lyrics only leaves out chords and tablature, and "Apply transposition" rewrites only the chords and the key.
- The editor shows song sheets with each chord over its syllable, and the source while the cursor is in the block (ADR-0031). Above each sheet, buttons transpose it by semitones, a menu shows the chords in English or German names, and "Lyrics only" hides the chords; none of this changes the note. "Apply transposition" writes the transposed chords into the note, after keeping the version before in the history; Undo takes it back.
- The editor engraves music written in ABC (`abc` blocks, format.md §5.6; ADR-0032): every tune of the block, with voices, lyrics and chord symbols, moved by `transpose=`. Field continuations (`+:`) and letters written as HTML entities (`&Uuml;`) or escapes (`\u00dc`) show as ABC 2.1 means them. A click on a note puts the cursor there in the source. A block with mistakes stays source, with a list of what is wrong; a click on an entry goes to the place. The music renderer (abcjs) is loaded only when a note has music.
- Scores play (F-17, ADR-0035): a bar above each score in the editor plays it on a piano the app brings along, so it works offline, and stops it. The bar also sets the tempo in percent and transposes the score and its sound by semitones. In a tune with several voices, each can be muted or played alone (M, S) to practise a part, and the accompaniment to the chord symbols can be switched off. These are view settings; the note does not change. On the iPhone, playback is meant to sound with the silent switch on (iOS 16.4 and later).
- Music menu (ADR-0013): Music in the bar under the note starts a score from a template (a melody with chords, two voices, or a choir score in four voices). In a score it sets the tune's key and metre, adds a voice with the clef you choose, a line of lyrics, a chord symbol or another tune, each as one change you can undo. It links to the ABC standard. A new manual page, `docs/manual/music.md`, explains scores, ABC in brief, playback, song sheets and exporting music.
- Exports show music (ADR-0033, ADR-0034). Scores (`abc` blocks) are engraved as in the editor, in black: inline in HTML and PDF, where their words stay text, and as pictures in ODT, DOCX and EPUB. Song sheets (`chordpro` blocks) put each chord over its syllable, transposed and named as the block says: as in the editor in HTML, PDF and EPUB, and as a line of chords over a line of lyrics in a monospace font in ODT and DOCX. A score that cannot be engraved stays ABC source and is listed in the report. File › Export… can add the ABC source under each score.
- Smart folders in the core (format.md 0.9 §9, ADR-0018): saved searches in `.notesapp/smart-folders.yaml` can be added, renamed, changed, removed, reordered and nested; keys and entries other tools wrote are kept, and a change made on another device at the same moment is not lost. Results follow each folder's sort order.
- Smart folders in the app: a "Smart folders" section above Tags (on the phone in the Tags view) lists the saved searches, nested. "Save" next to the search field keeps the current search as a folder; the ✎ button edits name, search, parent folder and order, or deletes the folder after asking (its subfolders move up, no notes are touched). Drag a folder by its ≡ handle to reorder it or drop it onto another folder to nest it; with the keyboard, the arrow keys on the handle do the same. Changes made on another device show up by themselves.
- Export can start one document of several notes with a table of contents, and number the pages of PDF, ODT and DOCX (ADR-0029): two new choices in File › Export…. The contents list every note with the page it starts on, linked to it; a table of contents turns page numbers on. In EPUB the contents are a page of the book besides the reader's navigation.
- In DOCX and ODT a photo turned only by its orientation, as phones store them, is turned upright in the file (ADR-0028): LibreOffice and other office programs showed it on its side.
- Exports convert HEIC, HEIF and TIFF pictures to JPEG, or PNG where they have transparency (ADR-0027), as most programs other than Apple's show them as broken or not at all. The vault is not touched; a picture that cannot be converted stays as it is and is named in the report. In ODT a picture taller than the page is made to fit, instead of being cut off.
- DOCX and EPUB export through Pandoc (ADR-0010, ADR-0025): when Pandoc is installed, File › Export… offers both and shows its version. Footnotes are real footnotes, pictures are inside the file, each note starts a new page in DOCX and a chapter in EPUB, and what Pandoc warns about goes into the report: an SVG drawing that stays SVG only in a DOCX, for want of `rsvg-convert`, is named there with how to add a PNG copy. In EPUB a picture is never taller than a page of the reader, and a long code block goes on over pages instead of being cut off. Pandoc is never bundled.
- File › Export… (desktop): export the open note or the notes in the list as HTML, PDF (macOS) or ODT, as one document or one file per note, on A4 or Letter, with or without the final line of tags. The open note is saved first. The report lists what is different from the notes, each note openable from it, and which files got a number because their name was already taken in the folder, where nothing is ever replaced. The result can be shown in Finder. An export into the vault is refused.
- ODT export in `schnipsle-export` (ADR-0010, ADR-0021): one file of one note or several with a new page per note, or a file per note that link to each other, on A4 or Letter. Pictures are inside the file, footnotes are real footnotes, and a note's title and dates go into the document's properties. Attachments stay behind and are reported. LibreOffice opens and converts every sample in CI.
- PDF export on macOS in `schnipsle-export` and `schnipsle-apple` (ADR-0021, ADR-0022): one PDF of one note or several with a new page per note, or a PDF per note, on A4 or Letter. Text can be selected, links stay links, and a note's title and dates go into the PDF. Wide tables and long words stay on the page. Links between separate PDFs become text and are reported.
- HTML export in `schnipsle-export` (ADR-0021): one note or several, as one file holding its pictures, as one document in a folder with copies of its attachments, or as a document per note. Front matter and a final line of tags are left out, links to notes point inside the export, raw HTML is cleaned, and a report lists pictures not found, attachments not included and links to notes not exported.
- Import pipeline in `schnipsle-import` (format.md §12, no UI yet): a dry run that reports what an import would add, update or skip and why; then the import itself, which stores attachments, keeps the source's dates, adds folder and source tags on a final line, snapshots every note it updates and writes the import log first. A note imported before is updated only if it was not changed here and is newer in the source. Lines such as `#define X` that turn into tags are pointed out in the report.
- Markdown import: File › Import… reads a folder of Markdown files, such as notes from another editor, or a single file. Each file becomes a note as it is, front matter of other tools included; a `title` in the front matter also becomes the note's heading, so the note shows the title it is named by (format.md 0.12, ADR-0020); subfolders become tags, and pictures and files the notes link to in the folder are copied into the vault. ChordPro songs (`.cho`, `.crd`, `.chopro`, `.chordpro`) become notes with their title and the song in a `chordpro` block. Choosing a folder inside the open vault, or one that contains it, is refused for every kind of import.
- Undo an import: File › Imports… lists the imports into the open vault, newest first, with what each brought in. Undo… shows first what would happen: notes the import added go to the trash, notes it updated get their previous version back from the history, and notes changed here since stay as they are, as does any note the undo cannot change (format.md 0.13 §12.4). Undo import then does exactly that and marks the import as undone; nothing is deleted for good. A later import of the same export adds the trashed notes again but leaves the kept ones alone. Notes already in the trash, such as those that came from Simplenote's trash, stay there, and both the import and the undo report say "in the trash" for them rather than "deleted".
- Links in notes open with ⌘-click (Ctrl-click on other systems), in live preview and in source mode: web pages and mail addresses in the default browser or mail app, pictures and files in the vault in their default app, and a link to another note opens that note here. A plain click still places the cursor to edit the link. A link to something missing says so in the status line. Desktop only for now.
- HTML import: File › Import… reads a folder of HTML files, such as web pages saved from a browser, or a single file. Each page becomes a Markdown note named after its first heading or its `<title>`, with its subfolders as tags; pictures saved with the page or embedded in it, and files it links to in the folder, are copied into the vault. Pages in Windows-1252 or ISO-8859-1 are read too.
- Simplenote import: File › Import… reads the zip Simplenote exports as it is (or its `notes.json`). Notes keep their ids, dates and pins, Simplenote tags become hashtags on a final line unless the text has them already, and notes from Simplenote's trash go to the trash here.
- File › Import… (desktop): pick an Apple Notes export, see what would be added, updated or skipped and why, then import with a progress bar; the result lists every note, each one openable. Dates and folders are read from Notes on request (macOS asks once whether Schnipsle may). Imported notes are searchable right away.
- Apple Notes import: reads the Markdown export together with `apple-notes-metadata.json`, so notes keep their dates and land in their real Notes folders with a matching tag. Notes' line-end spaces are removed where they change nothing, stray line separators dropped, and PDFs linked instead of shown as images. The report lists files without a matching note, locked notes, and notes the export left out because another note in the folder has the same title.
- `scripts/apple-notes-metadata.js` prepares an Apple Notes import (ADR-0019): run with `osascript -l JavaScript`, it writes `apple-notes-metadata.json` with each note's ID, folder and dates into the folder of a Markdown export, which leaves these out. It only reads Notes.
- Pinning: the Pin button next to History pins the open note, and pinned notes are listed first in the note list, tag folders and search results (marked 📌). It sets `pinned: true` in the front matter (format.md §4); unpinning removes the key. Nothing else in the note changes, not even `modified`, so pinning does not count as an edit.
- Test UI: open a vault folder, edit notes with autosave, reload external changes, resolve conflicts (spike).

### Changed

- In code — scores, song sheets, other code blocks, inline code and front matter — a `"` or `'` stays straight and `--` stays two hyphens when the system's smart quotes and dashes would change them, so typing ABC on the Mac no longer breaks chord symbols and names. Prose keeps the system's quotes, and a typographic quote typed on purpose or pasted stays.
- Scores whose lines of staves reach past the width abcjs gives them, such as a first line with two voices on each staff, are no longer cut off at the right, in the editor or in exports. In the bar above a score, each voice of a shared staff has its own name (before: "Soprano Alto" and "Voice 3"), and the voices have a line of their own, so a voice's M and S stay together.
- A note that starts with a heading of any level, such as `## Title`, now takes its title from that heading without the `#` marks (format.md 0.14 §5.2, ADR-0026): in the note list, in links, and in the names and titles of exports. The search index rebuilds itself once.
- Search results show a snippet of the note's text with the hits marked, even when the hit is in the title; before, a title hit showed the title a second time, which looked like a second result.
- Apple Notes import tells apart several notes with the same title also when they have tags: the metadata shows Notes' tags as placeholders, so the text is compared with and without its hashtags. A note matched only by title used to keep the time of the export and was updated by every re-import.
- iOS remembers the vault folder in a file in the app's Application Support folder instead of `UserDefaults`, excluded from backups since it only works on the device that made it. The folder picked with an earlier build is taken over automatically.
- Trash records store `original_path` relative to the vault root (`notes/…`, format.md 0.6); records written by earlier M1 builds are restored into `notes/` under their file name.
- Safer saving: the conflict check now runs after the new text is flushed to disk, right before the rename, and creating a note can no longer replace one created at the same moment by another device or process.
