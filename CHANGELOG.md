# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- Repository foundation: Cargo workspace (`schnipsle-core`, `-import`, `-export`, Tauri 2 shell), TypeScript UI, CI, dependency licence checks, macOS bootstrap script.
- Architecture decision records ADR-0001 to ADR-0019.
- Vault format specification, draft revision 0.10 (notes, front matter, tags, links, attachments, music in ABC, song sheets in ChordPro, history, trash, smart folders, imported notes and the import log).
- Hashtag extraction in `schnipsle-core` following format.md §5.3, with the specification examples as tests.
- Vault access in `schnipsle-core`: list notes (with iCloud placeholders), read, atomic write with conflict detection, create (spike, see docs/spikes/ios-vault.md).
- `tauri-plugin-vault-access`: iOS folder picker with security-scoped bookmarks and iCloud download requests (spike).
- File coordination on macOS and iOS (ADR-0015): notes are read and saved through `NSFileCoordinator`, so iCloud Drive and other apps cannot change a note between the conflict check and the save. New crate `schnipsle-apple`; `schnipsle-core` gains a `Coordinator` trait.
- Changes made elsewhere now arrive as file events instead of being polled every 3 s: `notify` on desktop, an `NSFilePresenter` on macOS and iOS. The UI gets one `vault-changed` event per burst of changes.
- iCloud sync conflicts are shown: when two devices changed a note before syncing, a banner offers to keep this version or use the other one. The version not kept is stored in the note's history (`.notesapp/history/<id>/`, format.md §7) before iCloud is told the conflict is resolved, and the note gets `id`, `created` and `modified` in its front matter.
- Every save keeps the note's front matter up to date (format.md §4): `id` and `created` are added the first time the app writes a note, `modified` on each change. Keys added by other tools are preserved, and a note is never rewritten just by opening it.
- Copies of a note with the same `id` (format.md §4), such as the `Name 2.md` copies iCloud Drive makes in a sync conflict, are shown in the conflict banner: keep this version or the copy's (the other text goes into the note's history and the copy is removed), or keep both as separate notes, in which case the later one gets a new `id`. Copies in other folders are found through the search index; copies in the same folder also while the index is still being built.
- New note editor (CodeMirror 6, ADR-0007) with inline live preview: headings, emphasis, strikethrough, inline code and links are shown formatted, their Markdown markers appear only on the line being edited, and task boxes can be ticked. A button switches to plain Markdown source; the choice is remembered. The front matter is shown muted, and front matter written on save no longer moves the cursor or enters the undo history.
- Note list: sort by recently changed or by title (ignoring case and accents). New notes are named after their title, and when you leave a note whose title changed, its file is renamed to match (format.md §3); renames never replace another file.
- Trash (format.md §8): Delete moves a note unchanged to `.notesapp/trash/`, with Undo; a Trash view lists deleted notes and restores them. Notes without `id` and repeated ids get their own trash names (format.md 0.5).
- Vaults follow the layout of format.md §1: a vault is a folder with `.notesapp/vault.yaml`, and its notes live in `notes/`. Picking a folder without `vault.yaml` asks first and then moves everything visible in it into `notes/` (relative links keep working; hidden files such as `.notesapp/` stay), so existing note folders, including the M1 test vault, are converted only with consent. A vault written by a newer format version, or with a damaged `vault.yaml`, opens read-only with an explanation. Picking a folder inside a vault is refused.
- Notes that turn up outside `notes/` (`.md` files and folders with notes at the vault root, e.g. saved by an older build on another device) are detected when the vault opens and when its root changes. A banner offers to move them into `notes/`: notes with a taken name get `-2`, `-3`, …, folders with a taken name stay where they are, and nothing is replaced.
- Images and other attachments (format.md §5.5, §6): paste or drop files into a note, or pick images with the Image button. Each file is stored once per content at `attachments/<h0h1>/<sha256>.<ext>`, with a sidecar recording its original name, and the note gets a link relative to it (`![name](../attachments/…)`; other files get a plain link). Live preview shows images, also ones next to the note; on the line being edited the Markdown appears in front of the image, which stays visible.
- Image and file links keep working when a note moves to another folder (format.md 0.7 §5.5, ADR-0016): when a restore from the trash falls back to `notes/`, or notes are moved in from the vault root, relative links that worked before are rewritten, and the previous text goes into the note's history. URLs, note links and links that were already broken stay as written.
- Version history for every note (format.md §7, ADR-0011): a version is stored after a 30-second typing pause, when you leave a note, before it is deleted, and before another version replaces it (a change from elsewhere, or either side of an editing conflict, which so far dropped the losing text). A version equal to the last stored one is skipped. When a vault opens, old versions are thinned in the background: all are kept for 7 days, then the last of each day for 90 days, then the last of each week.
- History view: the History button shows the open note's earlier versions, newest first. Pick one to read it (in preview or source, like the editor), then restore it (the text it replaces goes into the history first, and a change made elsewhere meanwhile stops the restore) or copy it as a new note with its own `id`.
- Tables (GitHub Flavored Markdown) show as tables in the live preview, with column alignment; their Markdown appears while the cursor is in the table. Cells show their text as written for now.
- History retention can be set per vault in `.notesapp/settings.yaml` (format.md 0.8 §7, ADR-0017): `history_keep_all_days` (default 7) and `history_keep_daily_days` (default 90).
- Own menu bar on the desktop: File (New Note, Open Vault…, Close Window), Edit, Window (Minimize, Zoom, Full Screen) and, on macOS, the app menu. "Close Window" no longer appears twice.
- Search index in `schnipsle-core` (ADR-0009): SQLite with FTS5 (bundled), per note its title, plain text, tags with their hierarchy, note links and linked files; a per-device cache that rebuilds itself when its schema changes or the file is damaged. The app keeps it current: a background sync when a vault opens (reading only files whose modification time or size changed), then change events and its own writes; trashed notes are indexed too.
- Tag folders (ADR-0008) in a collapsible tree above the note list (on the phone a Tags view of its own): every top-level tag with its note count, hierarchy levels (`#projekte` › `#projekte/tuner`) and combinations with co-occurring tags as intersections up to three tags deep, plus the untagged notes. A tag is shown in its most used spelling; the trash does not count. Picking a folder filters the note list; a line above it says what is shown, with "Show all".
- Full-text search in a search field above the note list: words match as prefixes ignoring case and diacritics, `"phrases"`, `#tags` (with their subtags), `-` to exclude, `OR` and parentheses; best matches first (titles count more), each with a snippet that marks the hits. Escape returns to what the list showed before. The trash is not searched.
- Performance test with 20,000 generated notes (N-03), run in CI in release mode: every search and tag-folder query must stay under 200 ms; on a Mac they take 2–48 ms.
- The search understands the full query language (`docs/manual/query-language.md`): `created:` and `modified:` with years, months, days, `today`, `yesterday`, `7d`/`2w`/`3m`/`1y`, comparisons and ranges, in your local time zone; `has:image|task|link`, `is:pinned|untagged`, `in:trash` (trash hits are marked and can be restored from the Trash view) and `tag:x`. The index rebuilds itself once for the new fields.
- Song sheets (` ```chordpro ` blocks, format.md §5.7) are searchable by their lyrics without the chord brackets and by title, subtitle, artist, composer and lyricist; ChordPro comments and tablature are left out. `has:chord` finds notes with chords, `chord:Am` notes with that chord. The index rebuilds itself once more.
- Smart folders in the core (format.md 0.9 §9, ADR-0018): saved searches in `.notesapp/smart-folders.yaml` can be added, renamed, changed, removed, reordered and nested; keys and entries other tools wrote are kept, and a change made on another device at the same moment is not lost. Results follow each folder's sort order.
- Smart folders in the app: a "Smart folders" section above Tags (on the phone in the Tags view) lists the saved searches, nested. "Save" next to the search field keeps the current search as a folder; the ✎ button edits name, search, parent folder and order, or deletes the folder after asking (its subfolders move up, no notes are touched). Drag a folder by its ≡ handle to reorder it or drop it onto another folder to nest it; with the keyboard, the arrow keys on the handle do the same. Changes made on another device show up by themselves.
- Import pipeline in `schnipsle-import` (format.md §12, no UI yet): a dry run that reports what an import would add, update or skip and why; then the import itself, which stores attachments, keeps the source's dates, adds folder and source tags on a final line, snapshots every note it updates and writes the import log first. A note imported before is updated only if it was not changed here and is newer in the source.
- `scripts/apple-notes-metadata.js` prepares an Apple Notes import (ADR-0019): run with `osascript -l JavaScript`, it writes `apple-notes-metadata.json` with each note's ID, folder and dates into the folder of a Markdown export, which leaves these out. It only reads Notes.
- Pinning: the Pin button next to History pins the open note, and pinned notes are listed first in the note list, tag folders and search results (marked 📌). It sets `pinned: true` in the front matter (format.md §4); unpinning removes the key. Nothing else in the note changes, not even `modified`, so pinning does not count as an edit.
- Test UI: open a vault folder, edit notes with autosave, reload external changes, resolve conflicts (spike).

### Changed

- iOS remembers the vault folder in a file in the app's Application Support folder instead of `UserDefaults`, excluded from backups since it only works on the device that made it. The folder picked with an earlier build is taken over automatically.
- Trash records store `original_path` relative to the vault root (`notes/…`, format.md 0.6); records written by earlier M1 builds are restored into `notes/` under their file name.
- Safer saving: the conflict check now runs after the new text is flushed to disk, right before the rename, and creating a note can no longer replace one created at the same moment by another device or process.
